# 导入图去白底（真透明）——设计规格

日期：2026-11-12
状态：**已实现**（`src/pdf_auto_crop/whiten.py` + `tests/test_white_background.py`）

## 1. 问题（实测）

用户诉求：导入的 PDF 图像默认带白色背景，希望能把背景变透明，以便叠加到其他图层上。

实测证据（`diag_out/probe_user_figs2.py`、`proto_scan2.py`、`probe_compress.py`）：

- 用户 E 盘 `models_evaluation\figures_R1` 下 **168 个 PDF，168 个都在源文件里自画了整页白色矩形**，
  那是 matplotlib 的 figure patch，不是软件的画布。
- 白底矩形永远画在内容流的**最开头**（实测偏移 103–115 字节），坐标区底白在 179–218 字节。
- 内容流体积：中位数 43 MB，最大 573 MB（单页 40 万条矢量路径）——**全流解析不可行**，
  但白底总在头部，窗口化扫描足够：扫前 64 KB 耗时 0.02–0.08 s。
- 画布侧的独立问题：`compositor_gui.py::_figure_image` 用 `get_pixmap(dpi=...)`（**无 alpha**），
  MuPDF 默认把纸涂白，于是每个导入的图在画布上都是一块不透明白板。

结论：**要真透明必须动源内容流**（矢量级），只改画布渲染只能骗眼睛，导出文件仍是白底。

## 2. 目标

1. 导入的图在画布上**不遮挡**下层：未被绘制的区域透出画布纸张。
2. 打开「去白底」后，**导出的 PDF 里**该图的背景是真透明（仍是矢量，可继续缩放/印刷）。
3. 不改动用户原始 PDF 文件。
4. 不破坏已有的矢量保留、缓存、布局存读、撤销等机制。

## 3. 方案

### 3.1 画布侧：alpha 渲染（无条件生效）

`_figure_image()` 改用 `get_pixmap(dpi=PREVIEW_DPI, alpha=True)`，
`Image.frombytes("RGBA", ...)`，画布用 Tk 8.6 的 RGBA PhotoImage 合成
（实测 Tk 8.6.13 支持）。

效果：源文件没画背景的图，本来就透；画了背景的，仍然不透——所以还需要 3.2。

### 3.2 导出侧：矢量白底剥离（可选开关）

在 `bake_figure()` 把源页复制进 scratch 文档之后、嵌入之前，
**改写该页内容流**：把「背景级」的近白色填充的绘制算子换掉。

- `f` / `F` / `f*` → `n`（只结束路径，不涂）
- `B` / `B*` → `S`，`b` / `b*` → `s`（保留描边，只去掉白色填充）

每个填充只改 **1 个字节**（两字节的算子改成 1 字节算子 + 1 个空格，流长度不变），
其余内容逐字节保持原样。

**为什么这样最安全**：不重建内容流、不重新序列化、不碰任何其他算子，
不存在「解析错一个 token 就毁掉整张图」的风险。

### 3.3 白底的判定规则

在内容流头部窗口（默认 64 KB）内扫描，记录：

- 图形状态栈（`q`/`Q`）里的**填充色**（`g`/`rg`/`k`/`sc`/`scn`）；
  `sc`/`scn` 遇到图案名（`/P0 scn`）或非 RGB 空间时标记为「颜色未知」→ 不动它。
- 当前路径（`m`/`l`/`c`/`v`/`y`/`h`/`re`）的包围盒。
  路径构造时快照当时的 CTM（`cm`）——路径在构造时定型，之后再 `cm` 不影响它。
- 路径绘制算子（`f/F/f*/B/B*/b/b*/S/s`）与只结束路径的 `n` 都要清空当前路径。

命中条件（三条全中才动它）：

1. 填充色是近白（RGB 三通道都 ≥ 0.99；CMYK 白 `0 0 0 0 k` 换算后同样命中）；
2. 该填充**盖住图自身面积**的 ≥ 10%（交集面积 ÷ 图区域面积）——
   整页底、坐标区底都命中，图例框、小白块不命中；
3. 该填充在扫描窗口内能找到（够不着就不动，不猜）。

**坐标系**（实测确定）：内容流坐标以 MediaBox 左下角为原点，裁剪框也在同一空间，
所以「内容坐标 → 本包的图区域坐标」= 减去 `page.cropbox` 的原点
（`whiten.frame_offset`）。实测：MediaBox `[10 20 210 220]` + CropBox `[50 50 150 150]`
的页面，帧偏移是 `(50, 50)`，不是 `(40, 30)`。

### 3.4 性能

| 环节 | 15 MB 流 | 143 MB 流 |
|---|---|---|
| 解码 | 0.06 s | 0.54 s |
| 窗口扫描 + 判定 | 0.02 s | 0.08 s |
| 回写（zlib level 1） | 0.15 s | 1.41 s |
| PyMuPDF `update_stream` 默认压缩 | 1.32 s | 14.95 s |

回写**不用** PyMuPDF 的默认压缩（实测慢 10 倍），
改为：自己 `zlib.compress(data, level)`（流 < 8 MB 用 level 6，更大用 level 1），
再 `update_stream(xref, compressed, compress=False)` + `xref_set_key(xref, "Filter", "/FlateDecode")`。
实测产物有效：角落 alpha = 0，页面内容完好。

**缓存**：剥离后的页面随 `bake_figure` 的产物一起按 `Figure.key` 缓存，拖动不重复算。

### 3.5 超大文件的兜底

单页内容流超过阈值（默认 256 MB）时**跳过剥离**，并在结果里说明原因
（实测最大那个文件 573 MB，剥离要 ~6 s 且占内存 >1 GB）。
跳过是安全的：图仍然正常显示，只是背景不透明。

## 4. 数据模型

`Figure` 增加字段：

```python
transparent_bg: bool = False
```

- 计入 `Figure.key`（缓存区分带不带剥离）；
- 进 `to_dict` / `from_dict`（布局存读要能还原）。

## 5. 界面

- **工具栏**：新增复选框「去白底」，紧挨现有的「白底」（导出页白底），
  作用是**之后导入**的 PDF 图的默认值（默认开）。
- **图形属性区**（「标签」页）：选中图形时多一个复选框「去白底（背景透明）」，
  可单独覆盖全局默认。
- 角度与背景是两个独立回调（`_on_figure_changed` / `_on_figure_strip_changed`）：
  写回角度时若顺带写背景，会把**过期的**背景设置带进图形。

## 6. 测试

- **模型层单测**（`tests/test_white_background.py`，32 项）：
  - 扫描器：`1 g` / `1 1 1 rg` / CMYK 白、图案色与未知空间不误判、
    字符串里的 `f` 不算算子、`q`/`Q` 与 `cm` 正确、裁剪框 `W n` 不算填充、
    多边形写法（matplotlib 的实际写法）也能找到；
  - 判定规则：整页底命中、坐标区底命中、图例框不命中、
    面积按**图自身**而不是页面算；
  - 补丁：改写后角落 alpha = 0、长度不变、其余字节逐字节相同、
    `B`→`S`、`b*`→`s `；
  - 烘焙链路：`transparent_bg=True` 的烘焙产物角落 alpha = 0，默认仍为 255，
    矢量完好（无位图）；
  - `Figure.key` 随开关变化；`to_dict/from_dict` 往返；
  - 原始文件不被改动。
- **冒烟**（`scripts/compositor_screenshot.py`，真实控件路径）：
  造一个带白底的整页图 → 导入 → 上画布 → 烘焙产物透明 →
  面板复选框能翻回白底 → 导出文件里白底真的让下层透出来。

## 7. 明确不做

- 不栅格化（输出保持矢量）。
- 不改用户原始 PDF（只在内存里的 scratch 副本上改）。
- 不扫描内容流深处（超出 64 KB 窗口的白色填充保持原样）。
- 不处理栅格图内部的白色（位图里的白像素去不掉，只能靠源文件用
  `savefig(transparent=True)` 重新导出）。
