# 层级与布尔运算 —— 设计规格

日期：2026-11-05
范围：`pdf-auto-crop` 组合器（`src/pdf_auto_crop/compositor.py` + `compositor_gui.py`）

## 1. 起点：现有【置于顶层】/【置于底层】是不正常的

面板上的两个按钮（`compositor_gui.py:1565`）接到 `_restack`（`compositor_gui.py:5505`），
而 `_restack` 做的是：

```python
items[i], items[j] = items[j], items[i]   # 只挪一格
```

三个问题：

1. **名不副实**：按钮写"置于顶层/底层"，实际只把选中的图在**图列表**里挪一格。
2. **只对图生效**：`_restack` 只看 `self._selected`（= `_sel_figs[-1]`）。选中图形、
   表格、文本时按钮毫无反应，静默失败。
3. **跨类型无法调层级**：图形、表格、文本分属 4 个列表，导出顺序被写死为
   图 → 图形 → 表格 → 文本 → 标签。

结论：不是小修，要重做。

## 2. 层级模型

### 2.1 全局层号

每个元素带一个全局层号 `z`（浮点）。绘制与导出都按 `z` 排序，同层按原来的插入顺序
（图 → 图形 → 表格 → 文本）排，保证旧文件打开后层级不变。

- 新元素：`z = 当前最大值 + 1`（新加的东西在最上面）。
- 旧文件没有 `z`：读入时全部为 0，靠"同层按插入顺序"还原原有层级。
- 任何一次层级调整后重新编号为 0,1,2,…，避免浮点漂移。

`Composition.stack_order()` 返回 `[(kind, index)]`，`kind ∈ {figure, shape, table, text}`。

### 2.2 四个动作

| 动作 | 语义 |
| --- | --- |
| 置于顶层 | 选中的元素移到全局栈顶 |
| 置于底层 | 选中的元素移到全局栈底 |
| 上移一层 | 与栈里紧挨着上面的那个元素交换（跨类型也算一层） |
| 下移一层 | 与栈里紧挨着下面的那个元素交换 |

多选时按**整块**移动：选中的元素保持相对顺序，作为一个块与相邻元素交换。
（与 PowerPoint 的"上移一层"一致。）

### 2.3 标签跟随它的图

标签是图的属性：标签的层 = 它的图的层 + 0.5（刚好在图之上）。

这样"置于底层"之后不会出现标签悬在上面的怪相。同时也**保持了旧文件的样子**：
旧文件里所有元素的层都是 0，标签的层是 0.5，仍然在所有元素之上——和引入层级
之前完全一样。

## 3. 布尔运算

### 3.1 范围

只作用于**图形元素**（矩形、圆角矩形、椭圆、PPT 形状）。线条、箭头、花括号是开放
路径、没有面积，不参与运算。表格、文字、图片不参与。

### 3.2 运算方式：PDF 原生矢量裁剪

不引入任何新依赖，用 PDF 自己的裁剪路径与填充规则算出结果：

| 运算 | PDF 做法 | 结果 |
| --- | --- | --- |
| 并集 union | 一条复合路径，非零填充（各子路径同向） | A ∪ B ∪ … |
| 交集 intersect | 依次 `W n` 裁到每个图形，再填充 | A ∩ B ∩ … |
| 差集 difference | 先裁到基准图形，再用 `W*`（奇偶规则）逐个减去其余 | A − (B ∪ …) |
| 排除 exclude | 一条复合路径，奇偶填充（`f*`） | A ⊕ B ⊕ … |

要点：

- **差集的基准**是最下层的那个图形（层级顺序），其余图形都是被减去的。
- **边框**沿着结果的真实轮廓画：对每个参与运算的图形，用"裁剪到它减去其余图形"
  （或交集时"裁剪到交集"）的方式描边，露出来的边就是结果的边，不会出现并集
  中间的内部接缝。
- **填充**统一为"裁剪到结果区域，再填充所有图形的复合路径"。
- 渐变填充同样可用：把渐变画进结果区域的裁剪区即可。

### 3.3 数据

`Shape` 增加两个字段：

- `op: str = ""` —— 空串表示普通图形；否则是 `union` / `intersect` /
  `difference` / `exclude`。
- `parts: List[Shape] = []` —— 参与运算的原始图形（用户空间坐标，自带各自的
  kind / start / end / rotation）。

布尔结果本身也是一个 `Shape`（`kind = "boolean"`）：

- `start` / `end` = 所有 parts 的包围盒（用户空间），用来拾取、移动、缩放。
- 样式（边框色、宽、线型、透明度、填充色、填充透明度、渐变、标题文字）取自
  **基准图形**（最下层的那个），用户之后可以照常改。
- `rotation` 是整个结果绕自身中心的旋转，渲染时作用到每个 part 的盒子上。

移动 → 平移每个 part；缩放 → 按比例缩放每个 part 的盒子；旋转 → 绕结果中心
旋转每个 part 的盒子。

### 3.4 结果取代原图形

参与运算的图形被结果取代（与 PowerPoint 一致），可用 Ctrl+Z 撤销找回。

### 3.5 预览与导出同源

预览不是另画一遍，而是把**同一段 PDF 内容流**写进一张临时小页面，渲染成位图贴到
画布上。所以屏幕上看到的和导出的完全一致；导出仍是真矢量（不栅格化）。

## 4. 界面

右侧属性栏，笔记本页签下方：

```
┌───────────┬───────────┐
│  置于顶层  │  置于底层  │
├───────────┼───────────┤
│  上移一层  │  下移一层  │
└───────────┴───────────┘
```

四个按钮对当前选中的任何东西生效（图 / 图形 / 表格 / 文本，可混选）。

布尔运算按钮放在同一栏，四个：并集 / 交集 / 差集 / 排除。
选中少于 2 个图形时按钮变灰。

## 5. 测试

- 模型层单测：
  - `stack_order()` 在旧文件（无 z）上还原原有顺序；
  - 置顶/置底/上移/下移对单选、多选、跨类型的行为；
  - 布尔结果的四个运算在导出 PDF 里的**实际像素**（并集面积变大、交集变小、
    差集有缺口、排除有两块），并断言**没有图片**（仍是矢量）；
  - 布尔结果的移动/缩放/旋转；
  - 存读往返（`to_dict` / `from_dict`）不丢 `op` / `parts` / `z`。
- 真实控件冒烟：按钮能点、层级真的变了、布尔后画布上只剩一个结果图形。

## 6. 不做的事

- 不给表格/文字/图片做布尔运算。
- 不做多边形的精确布尔几何（结果区域由 PDF 的填充规则给出，不是重新算出来的
  多边形；因此结果不能再单独编辑某一个 part）。
- 不引入 shapely 等第三方几何库。
