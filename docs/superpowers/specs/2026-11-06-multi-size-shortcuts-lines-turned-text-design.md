# 多选同样大小、快捷键、正交线段、旋转文字 —— 设计规格

日期：2026-11-06
范围：`pdf-auto-crop` 组合器（`src/pdf_auto_crop/compositor.py` + `compositor_gui.py`）

## 1. 用户的四条要求

1. 对齐和「等大 / 同宽 / 同高」目前只支持选择两个元素，要扩展到多个元素。
2. 常用的功能除了有按钮之外，还应该配快捷键。
3. 很难绘制绝对水平和数值（指定长度）的线段。
4. 字体旋转以后（比如变成竖向），软件画布上渲染出来的位置和朝向与导出的 PDF 不一致。

## 2. 同样大小：支持任意多个元素

### 2.1 参照元素

规则不变：**后选的是参照**。参照元素自己不动，其余选中元素全部改成和它一样。

两个元素时与从前完全一致（`units[1]` 是参照）；三个以上时，参照是**最后选中的那一个**。

选取顺序原来没有记录：`_sel_figs` / `_sel_shapes` / `_sel_texts` / `_sel_tables`
各自是一个列表，跨类型的先后是排不出来的。因此新增 `self._sel_order`，
记录「(kind, index)」被点中的先后，作为**参考用**的状态：

- `_match_size` 用它找参照；
- 它与当前选择对不上时（撤销、删除之后）退回 `units[-1]`。

### 2.2 三种「一样大」

| 方式 | 含义 |
| --- | --- |
| 同宽 | 保持自己的长宽比，宽度取参照的宽度 |
| 同高 | 保持自己的长宽比，高度取参照的高度 |
| 等大 | 宽和高都取参照的（可能拉伸变形） |

计算搬到模型层：`comp.match_size_rect(target, source, how)`，可单测。

组合体算一个元素（`selection_units` 已经是这样）。

### 2.3 对齐本来就支持多个

`comp.align_target()` 把所有选中元素的**并集外框**当参照，所以「左对齐」把所有左边缘
对到最左那个。三个、十个都一样。补一条测试把它钉住，并在提示文字里写清楚。

## 3. 快捷键

### 3.1 原则

- 单键快捷键只在**画布**上生效，且焦点在输入框里时不生效（否则打字会切工具）。
- 组合键在面板上生效，焦点在哪儿都行。
- 快捷键要能查：工具栏加一个「快捷键…」按钮，弹出一张表。

## 4. 正交的线段与数值长度

### 4.1 Shift 约束

画直线、箭头、双箭头时按住 `Shift`，终点被拉到水平或竖直方向：

- 横向拖得多 → 终点与起点同高（水平线）；
- 纵向拖得多 → 终点与起点同宽（竖直线）。

模型层：`comp.constrain_to_axis(start, end)`。

只对**线段**（直线、箭头、双箭头）生效——用户要的是线段，别的形状保持原来的手感。

### 4.2 长度 mm

图形属性页新增「长度 mm」输入框（行 8，其余各行后移）。

- 直线/箭头：长度 = 起点到终点的距离。改长度时**方向不变**，只改长短。
- 其它形状：长度 = 外框的长边。改长度时整个外框**等比缩放**。

长度是算出来的量，不存进文件；面板显示选中元素当前的长度。

## 5. 旋转文字：画布与导出必须一致

### 5.1 导出是怎么摆的（准绳）

`comp.place_rendered()`：

1. 把渲染页**绕自己的中心**顺时针转 `angle`；
2. 再平移，使**基线起点**落在锚点上。

### 5.2 画布原来错在哪

画布原来把旋转后的墨迹**中心**放在文字位置上，而且这个偏移是按**没旋转**的墨迹算的。
文字一转，基线起点就跑到了别处——这就是「位置和朝向对不上」。

### 5.3 改法：画布用同一份渲染页、同一套规则

- 新增 `comp.RenderedText(path, origin)`：渲染好的页 + 基线起点在该页里的位置。
- `comp.render_text_pdf(item)` 统一处理三种文字：普通字、纯公式、文字+公式混排。
- `place_rendered(..., origin=...)` 可以直接给定基线起点，不用再猜。
- 画布 `_draw_turned_text` 改成：
  1. 渲染**整页**（`alpha=True`，纸是透明的，不会出现白框）；
  2. 绕页中心顺时针转同样的角度；
  3. 摆到基线起点落在锚点上。

于是画布和导出用的是**同一份 PDF、同一套摆放规则**，不可能再差。

### 5.4 顺带修好的一处真 bug

混排文字（"公式：$x^2$"）在导出时**根本不看 `rotation`**：`_draw_text_with_math()`
直接把各段写上去就返回了。所以旋转过的混排文字，导出是不转的。

改法：转动的文字一律先渲染成一页，再带角度摆上去——和普通转动文字走同一条路。
